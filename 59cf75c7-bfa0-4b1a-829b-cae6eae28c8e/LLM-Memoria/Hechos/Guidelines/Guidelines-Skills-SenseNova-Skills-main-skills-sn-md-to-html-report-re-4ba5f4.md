# 01-aesthetic-direction.md

## Resumen
Este documento establece un protocolo para definir la dirección de diseño visual antes de generar código HTML, enfocándose en extraer señales del contenido (dominio, emoción, herramientas) para derivar una identidad coherente. Su objetivo es evitar diseños genéricos y asegurar que cada elemento visual sirva a la narrativa específica del reporte.

## Datos clave
- **Proceso**: Extraer señales de contenido -> Brainstormear 2-3 direcciones distintas (incluyendo opuestas en tono) -> Seleccionar una basada en la tarea del contenido.
- **Sistema Compacto**: Definir dirección mediante tokens: Color (4-6 hex con semántica), Type (display/body/mono), Layout (concepto + wireframe ASCII), Signature (elemento memorable único).
- **Restricciones de color**: Base hue derivado del dominio, no preferencias personales; evitar gradientes genéricos o colores sin significado.
- **Tipografía**: Separación clara entre display (carácter) y body (lectura); prohibido usar Inter/Roboto/Arial por defecto; obligatoria fuente china Noto/Souyuan si aplica.
- **Texturas y animaciones**: Deben ser sutiles, de bajo contraste y servir a la comprensión del tema; incluir soporte `prefers-reduced-motion`.
